DeviceEnrollments

One row per enrolled person per device — the server's only record of who's allowed to sign in offline, and the one place an epoch bump actually lives.

Type
DynamoDB table, on-demand billing
Defined in
amplify/backend.ts
Keys
PK deviceId, SK userId

Fields: devicePubKey, userPubKey (registered once at enrollment), epoch (bumped only by an explicit admin action — Task 8's revocation), status, lastIssuedExpiry. No Lambda in this backend writes here except the enroll Lambda, and only via GetItem/PutItem — never a broader grantReadWriteData() surface.

Physical resources were recreated once during Task 4a after fixing a circular nested-stack dependency between the function's stack and this table's — same deviceId/userId key shape throughout, no data-model change. Currently RemovalPolicy.DESTROY, same MVP-sandbox posture and same before-real-devices caveat as the KMS issuer key.
