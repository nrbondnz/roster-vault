AppSync — enroll Mutation

A single custom GraphQL mutation, deliberately not modeled through Amplify's data construct.

Type
AWS AppSync GraphQL API
Defined in
amplify/appsync/schema.graphql, amplify/backend.ts
Authorization
Existing Cognito User Pool — AppSync verifies the ID token itself

mutation enroll(deviceId, devicePubKey, userPubKey): EnrollResult! — resolved directly by a Lambda (not Amplify's model-CRUD path), since the enrollment/refresh contract is bespoke: sign a token, don't just read/write a row. deviceId is generated client-side once per device and passed in, not derived server-side — the server has no way to know a device's identity except what the device asserts and binds into its own keypair.

Called as a plain authenticated HTTPS GraphQL POST from EnrollmentService.enroll — not through the typed amplify_api client, since this endpoint sits outside Amplify's data category entirely.
