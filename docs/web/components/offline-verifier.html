OfflineVerifier

"The actual hard requirement" — everything this whole project exists to prove happens inside this one class.

Type

Defined in

Zero — no http/Amplify import, enforced by construction

Runs every check in order, short-circuiting on the first failure: signature (via dart_jsonwebtoken, against the issuer public key baked into the app at build time) → expiry → device-id → epoch → challenge-response. The epoch check compares against a value separately persisted on-device at the last successful enroll/refresh — deliberately not the token's own epoch claim, which would make the check a tautology that always passes.

The challenge-response step signs a fresh random nonce with the person's hardware-backed key (UserIdentityService.signChallenge) and verifies it against their stored public key — proving possession of the private key, not just a copied token blob. biometric_signature signs via plain JCA SHA256withECDSA (confirmed by reading its Android source directly, not guessed) — always DER-encoded, so the signer converts to the fixed-width 64-byte raw r‖s format JWS needs, the same conversion the enrollment Lambda already does for KMS's own DER output.

Proven with 11 table-driven tests against real openssl-generated P-256 keypairs — every failure mode independently, two meaningful combinations, and the epoch comparison direction tested both ways (the exact one-character bug class this project's own review checklist calls out by name). Demonstrated on real hardware with the device's network genuinely disabled — see the Airplane Mode flow.
