KMS Issuer Signing Key

Trust Anchor 1 — signs every offline capability token; the private key never touches app memory, and never touches Lambda memory as a private key either.

Type
KMS asymmetric CMK, ECC_NIST_P256, SIGN_VERIFY only
Defined in
amplify/backend.ts
Grants
only kms:Sign to the enroll Lambda — no broader grant exists

This key type cannot decrypt — the key usage is SIGN_VERIFY only, so there is no decrypt code path to accidentally expose. Only the public half ever ships in the app, baked in at build time (lib/services/issuer_public_key.dart) via kms:GetPublicKey, so signature verification is pure local math with no network call — this is the single most important property to get right and keep right, per this project's own Review Agent checklist.

Currently RemovalPolicy.DESTROY with a 7-day pending window — accepted during MVP/sandbox development since no device is enrolled against a live deployment yet, flagged explicitly as something that must switch to RETAIN before any deploy with real enrolled devices depending on it.
