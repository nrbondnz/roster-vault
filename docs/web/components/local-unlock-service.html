LocalUnlockService

Ties a person's PIN to their own encrypted partition — the fourth on-screen milestone (Task 6), a real PIN gate, not a UI-only check.

Type
Dart service class
Defined in
lib/services/local_unlock_service.dart
Key methods
isSetUp, setUpPin, unlock

A deliberate, documented design choice: the architecture's literal K_user = HKDF(K_device, user_id) formula has no PIN in it — anyone who can read K_device can derive the same K_user without ever entering a PIN, in tension with the architecture doc's own prose ("can't read another profile's data without that profile's own local factor"). Resolved by giving the PIN a genuine, separate job: it PIN-wraps the enrollment token itself (via PinService, Argon2id-derived — real key material, not a redundant gate) as a row inside the K_user-encrypted partition, rather than being mixed into the database key. Raw file theft alone needs K_device; device compromise alone needs the PIN; only both together succeed.

unlock() always succeeds at opening the partition — K_user doesn't depend on the PIN, by design — the actual gate is entirely in the PIN-unwrap step afterward. Never throws for a wrong PIN; returns null, the same contract PinService.unwrap already uses.
