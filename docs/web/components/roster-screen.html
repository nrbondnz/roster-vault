Set as MaterialApp.home in lib/main.dart — AuthGate (Cognito sign-in) and the enrollment screen are now a sub-route reached from here via "Add a person," not the app's forced entry point they were through Task 6. Tapping a name shows a PIN dialog (after a lockout check via PinLockoutService, Task 9) and, on success, pushes ProfileHomeScreen with the recovered token.

"Add a person" is disabled ("Add a person (offline)") whenever connectivity_plus reports no real connection — per docs/roster-vault/Architecture/Multi-User Partitioning.md's "Roster Management Is an Online-Only Surface," greyed out honestly rather than left enabled to fail confusingly partway through a Cognito sign-in.

A real bug caught live on-device, not in review: the roster-refresh callback was originally an arrow-body setState assignment, whose value is the assignment expression itself (a Future) — Flutter's setState explicitly rejects a callback that returns a Future at runtime. The write succeeded but the roster silently never refreshed. Fixed to a block body.
