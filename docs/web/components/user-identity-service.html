UserIdentityService

Trust Anchor 3 — one keypair per enrolled person per device, and the production challenge-response signer OfflineVerifier calls.

Type

Defined in
lib/services/user_identity_service.dart
Key alias
roster_vault_user_key_<userId>, one per person

ensureUserKeyPair mirrors DeviceIdentityService's exact get-before-create pattern, generalized to a per-user alias. signChallenge builds the ES256 JWS signing input (matching the enrollment Lambda's own header/payload shape), signs it via biometric_signature.createSignature, and converts the DER result to the fixed-width raw r‖s format — resolved by reading the plugin's Android source directly (Signature.getInstance("SHA256withECDSA"), standard JCA, always DER; no P1363 path exists in the plugin at all), not guessed. A wrong guess here would have silently shipped a challenge-response that always fails on real hardware — worse than a clearly-flagged gap, which is why this was deliberately left unimplemented until real device access made the real answer checkable.
